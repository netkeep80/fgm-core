# Координаты и кубическая иерархия FGM

Контракт [C02](https://github.com/netkeep80/fgm-core/issues/6) дополняет [выборку поля FGM-0](fgm-0.md). Нормативное требование — [FGMC-SPACE-001](../requirements/FGMC-SPACE-001.rg.yaml).

## Пространства и единицы

Мировое и локальное пространства правосторонние. Мировая ось Z направлена вверх. Координаты поля экземпляра задаются тройкой `p = [x, y, z]` в единицах длины модели. Размещение задают мировая позиция начала координат `t`, матрица поворота `R` и положительный равномерный масштаб `s` в мировых единицах на единицу длины модели. Векторы в формулах записаны столбцами. Столбцы `R` задают направления локальных осей в мире.

~~~text
world(p) = t + s · R · p
object(w) = Rᵀ · ((w − t) / s)
Rᵀ · R = I
det(R) = +1
~~~

Масштаб, положение и поворот одинаковы для всех участков одного экземпляра. Для изменения ориентации кубов в мире применяется поворот экземпляра. Внутри его локальной системы кубы выровнены по общим осям. Внешняя система размещает экземпляры в своих мировых единицах и преобразует адреса игрового мира в адреса FGM.

## Адрес куба и чанка

Сетка в координатах экземпляра имеет исходную длину ребра `h > 0` в единицах модели. Адрес куба — целый уровень `l ≥ 0` и тройка целых индексов `i = [ix, iy, iz]`. Индексы могут быть отрицательными. На каждом следующем уровне ребро вдвое короче. Восемь дочерних адресов образуются выбором `b ∈ {0, 1}³`.

~~~text
edge(l) = h / 2ˡ
child(l, i, b) = (l + 1, 2·i + b)
object(l, i, u) = edge(l) · (i + u)
cell(l, i, p) = p / edge(l) − i
~~~

Для владения точкой нормированная координата каждой оси принадлежит полуоткрытому отрезку `[0, 1)`. Владелец точки на заданном уровне имеет адрес `floor(p / edge(l))` по каждой оси. Например, при `h = 1` координата `x = −0,25` принадлежит ячейке `ix = −1` уровня 0, а координата `x = 0` — ячейке `ix = 0`. Для выборки на гранях, рёбрах и вершинах используется замкнутый куб `[0, 1]³`. Обратное преобразование `cell(l, i, p)` даёт координату относительно данного куба, включая значения вне него.

Чанк уровня `l` объединяет `N³` кубов этого уровня, где `N` — заданное положительное целое число. Индекс чанка — `q = floor(i/N)`, локальный индекс куба — `r = i − N·q`. Все компоненты `r` принадлежат `[0, N)`, в том числе при отрицательных индексах. Например, для `i = [−5, −1, 4]` и `N = 2` получаются `q = [−3, −1, 2]` и `r = [1, 1, 0]`. Чанк задаёт группировку вычислений. Его граница не меняет адрес точки или значение поля.

## Общая точка разных кубов

Для выборок в двоичной иерархии точка внутри куба записывается как `u = m / 2ᵏ`. Здесь `k` — неотрицательное целое число, а каждая целая компонента `m` лежит от `0` до `2ᵏ` включительно. Точный адрес точки относительно исходной сетки выражается так.

~~~text
e = l + k
n = 2ᵏ·i + m
p = h · n / 2ᵉ
~~~

Пока `e > 0` и все компоненты `n` чётные, делим их на два и уменьшаем `e` на один. Итоговая пара `(n, e)` единственна для этой точки в сетке экземпляра. Начало сетки имеет `n = [0, 0, 0]`, `e = 0`. При обмене адресами между экземплярами контекст экземпляра и его сетки входит в идентичность точки.

Например, для куба `(l = 0, i = [−1, 0, 0])` локальная точка `[1, 1/2, 1/2]` и для куба `(l = 1, i = [0, 1, 0])` локальная точка `[0, 0, 1]` дают одну пару `(n = [0, 1, 1], e = 1)`. При `h = 3` обе стороны выбирают поле в `[0, 3/2, 3/2]`.

Адрес и принадлежность кубу вычисляются в целых числах. Для точной точки адрес владельца уровня `l` равен `floor(n·2ˡ/2ᵉ)`. Дробное значение для выборки переводится из канонического адреса одинаковым способом для обеих сторон стыка. Обратные преобразования произвольных вещественных координат выполняются с числовым допуском. Они не используются для установления точного равенства адресов. Представление больших координат и межплатформенные допуски относятся к [C05](https://github.com/netkeep80/fgm-core/issues/9) и [C06](https://github.com/netkeep80/fgm-core/issues/10).

## Материя, поверхность и коллизии

Для непрерывного поля формы `F` из C01 область материи определяется как замыкание множества `{p | F(p) < 0}`. Семантическая поверхность — граница этой области. В точке на внутреннем стыке двух соприкасающихся частей значение может быть нулевым, хотя точка лежит внутри замыкания. Пример — два прямоугольных блока, соприкасающихся по грани. Середина этой грани окружена материей. У внешней поверхности в любой окрестности точки есть и материя, и внешняя область. Область, целиком имеющая нулевое поле и окружённая воздухом, сама по себе не добавляет материи.

Для источника `volume` непрерывность относится к способу выборки его снимка. Сама запись воксельной маски задаёт дискретные исходные факты. Правила преобразования масок в поле требуют явного контракта источника.

Визуальный рендерер извлекает и уточняет поверхность, согласует сетки на стыках и применяет художественный профиль. Один экземпляр дерева на 2×2×4 клетки вычисляет одну форму ствола и ветвей во всех 16 адресуемых участках. Ствол может проходить внутри нескольких участков. Воздух остаётся пустотой. При разных уровнях детализации общий адрес даёт общую точку поля. Согласование топологии, нормалей и переходных сеток проверяется в [V02](https://github.com/netkeep80/fgm-renderer/issues/6#issuecomment-6875487151) и [V06](https://github.com/netkeep80/fgm-renderer/issues/10).

Игровые коллизии, проходимость и линия видимости вычисляются игровым слоем. LOFT в UFO задаёт исходные тактические маски. Эти маски ограничивают восстановление объекта, а его видимая форма может иметь отличающиеся фаски, фактуру и силуэт деталей. Адаптер определяет принадлежность исходных клеток экземпляру и переводит их размеры в координаты поля. Исходной прямоугольной клетке может соответствовать область из нескольких кубов FGM. [Декодирование LOFT](https://github.com/netkeep80/fgm-regenerator/issues/7) · [Граница визуального профиля](https://github.com/netkeep80/fgm-core/issues/13)

## Исполняемые примеры

[Синтетические проверки](../tests/fgm-space.test.mjs) используют `BigInt` для адресов и `Number` для координат выборки. Исполнитель примеров принимает уровни и суммарные показатели степени до 1023 включительно. При переводе адреса в координату сначала вычисляется величина в рёбрах исходного куба, затем применяется длина ребра. Для обратного вещественного преобразования нужны представимые длина ребра уровня и промежуточные координаты. Математический контракт адреса использует целые произвольной величины. Для матрицы в примерах применяется допуск `10⁻¹²` на ортонормальность и определитель.

Проверяются соседние уровни, общая вершина восьми кубов, границы чанков, перенос, поворот, масштаб и выборка общего поля дерева. Исполнитель различает неверный адрес или размер чанка (`E_SPACE_ADDRESS`), неверную точку (`E_SPACE_POINT`), неверное размещение или длину исходного ребра (`E_SPACE_TRANSFORM`) и выход за числовой диапазон преобразования (`E_SPACE_NUMERIC`).

~~~sh
node --test tests/fgm-space.test.mjs
~~~
