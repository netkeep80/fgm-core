# Эталонная выборка FGM на CPU

C05 реализует библиотеку C++20 для загрузки пакета и выборки формы и семантического материала. [C05](https://github.com/netkeep80/fgm-core/issues/9) · [FGMC-EVAL-001](../requirements/FGMC-EVAL-001.rg.yaml) · [Пакет C04](fgm-package.md)

## Сборка и интерфейс

~~~sh
cmake -S . -B build
cmake --build build --config Release
ctest --test-dir build -C Release --output-on-failure
~~~

Требуются компилятор C++20 и CMake 3.24 или новее. Цель `fgm::cpu` предоставляет заголовок `<fgm/evaluator.hpp>`. Сборка использует установленную библиотеку nlohmann/json версии 3.12.0 или получает архив той же версии с проверкой SHA-256. Для сборки без сети можно указать исходники через `FETCHCONTENT_SOURCE_DIR_NLOHMANN_JSON`. Лицензия зависимости — MIT. [Исходники зависимости](https://github.com/nlohmann/json/tree/v3.12.0)

~~~cpp
const auto object = fgm::Evaluator::from_package(bytes);
const auto local = object.sample_local({1.0, 0.0, 0.0});
const auto world = object.sample_world({1.0, 0.0, 0.0}, fgm::Placement{});
~~~

`from_package` читает UTF-8 JSON и проверяет версии `fgm-package/1`, `fgm-0/1` и вложенную `fgm-0`. Неизвестные обязательные поля и узлы, ссылки вперёд и повторные ключи отклоняются. Все узлы проверяются при подготовке. Повторные ссылки используют одну подготовленную форму. При выборе материала используются приоритет и устойчивый идентификатор вклада. Обе функции выборки возвращают скаляр и, для отрицательного вклада, материал и идентификатор. Обозначение материала корневой программы уступает явно заданному материалу вклада по C04. Камера и профиль рендера отсутствуют во входах. [Операции C01](fgm-0.md) · [Композиция C03](fgm-geometry.md)

При наличии внешних объёмов вызывающая сторона передаёт резолвер, который проверяет формат и SHA-256 байтов и возвращает функцию выборки неизменяемого снимка. Исполнитель связывает каждый дескриптор при подготовке и хранит функции для дальнейшей выборки. Для параллельных запросов резолвер должен вернуть функции, безопасные для одновременного чтения. Каноническая запись и вычисление хешей описаны в C04. C05 читает этот формат и вычисляет поле.

## Координаты и числовая модель

`sample_world` переводит мировую точку в локальную по формуле C02. Масштаб должен быть положительным, матрица ортонормальной с определителем +1. Абсолютный допуск проверки матрицы равен `1e-12`. Значение поля и в локальной, и в мировой функции остаётся в единицах модели. Для чанка вызывающая сторона передаёт точку, полученную из канонического адреса C02. Вычисление адресов остаётся на стороне потребителя. [Координаты C02](fgm-space.md)

Числа интерпретируются как конечные IEEE 754 binary64. Нуль результата приводится к положительному нулю. Точное равенство проверяется на примерах, выбранных для точного вычисления. Для сравнения результатов с промежуточным округлением используется `abs(a-b) ≤ 1e-12 × max(1, abs(a), abs(b))`. Классификация материала использует строгий знак. Округление может дать ненулевую выборку на математической границе. Для сверки классификации используются либо точно вычисляемые граничные точки, либо точки с запасом от нуля. Более широкий кроссплатформенный корпус относится к [C06](https://github.com/netkeep80/fgm-core/issues/10).

Валидатор сообщает исключение `fgm::Error` с кодом контракта. `E_JSON` включает неверные входные байты, синтаксис, дубли ключей и числовой литерал вне поддерживаемого диапазона JSON-парсера. `E_VOLUME` означает отсутствующую привязку или отказ резолвера либо источника. `E_NUMERIC` означает неконечный результат узла C01. `E_GEOM_VALUE` означает неверную локальную точку или неконечный результат сглаживания. Ошибки мирового преобразования используют `E_SPACE_TRANSFORM`, `E_SPACE_POINT` и `E_SPACE_NUMERIC`. Лимиты вычислений и размер допустимого графа относятся к [C07](https://github.com/netkeep80/fgm-core/issues/11).

Проверки используют синтетическую панель C04, примитивы, операции CSG, поворот и масштаб, зависимости от объёма и диагностику. [Тест C++](../tests/fgm-eval.test.cpp)
