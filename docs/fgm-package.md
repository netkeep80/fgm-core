# Канонический пакет FGM

Кандидат C04 задаёт переносимую запись одной модели и рецепта её получения. [C04](https://github.com/netkeep80/fgm-core/issues/8) · [FGMC-SERIAL-001](../requirements/FGMC-SERIAL-001.rg.yaml)

## Структура пакета

Пакет — объект JSON с четырьмя обязательными полями.

| Поле | Значение |
| --- | --- |
| `format` | Строка `fgm-package/1`, версия структуры пакета. |
| `interpreter` | Строка `fgm-0/1`, редакция семантики вычисления C01 и C03. Версия конкретной сборки интерпретатора ведётся отдельно. |
| `model` | Объект с непустым массивом `contributions`, семенем `seed` и каталогом `volumes`. |
| `generation` | Объект с идентификатором `algorithm`, версией `version`, каталогом исходных ресурсов `resources` и явными параметрами `parameters`. |

Ключи каталогов, идентификаторы вкладов, семантических материалов, алгоритмов и форматов объёмов имеют вид `[a-z][a-z0-9_]*`. Семя и контрольные суммы — 64 строчных шестнадцатеричных символа. Версия генератора — три десятичных целых через точку, без знаков и начальных нулей. Значение параметра — конечное число или вектор из трёх таких чисел. Ресурс задаётся парой из логического идентификатора в каталоге и SHA-256 его байтов. Рабочие пути остаются у вызывающей стороны.

Каждый вклад содержит `id`, `material`, `priority` и `field`. Идентификатор уникален в модели. Приоритет лежит в диапазоне безопасных знаковых целых binary64, от `−(2⁵³−1)` до `2⁵³−1`. Используется композиция в локальных координатах экземпляра. Камера, художественный профиль, уровень детализации и мировое размещение задаются потребителями. [C02](fgm-space.md) · [C03](fgm-geometry.md) · [C09](fgm-visual.md)

| `field.op` | Остальные поля |
| --- | --- |
| `program` | `program` содержит программу C01 с её собственной версией `fgm-0`. `parameters` содержит её явные привязки. Скалярное значение корня задаёт форму вклада. Материал вклада задаёт `material` на уровне вклада. [C01](fgm-0.md) |
| `smooth_union` | `left`, `right`, `allowed` и необязательное `protected` задаются такими же полями формы. Положительное конечное `width` задаёт размер поправки по формуле C03. [C03](fgm-geometry.md) |

Элемент `volumes` содержит `format` и `sha256`. Каждая ссылка `volume` из программы разрешается в этот каталог, в том числе из узлов, которые не достижимы из корня. При исполнении резолвер связывает дескриптор с функцией выборки. Резолвер отвечает за доступность источника, поддержку его формата и проверку SHA-256 исходных байтов перед выборкой. Проверка структуры пакета подтверждает ссылки и дескрипторы. Форматы содержимого источников и их выборка задаются отдельным контрактом.

## Канонические байты

1. Считываем корректный UTF-8 JSON без BOM. Повтор ключа в одном объекте, включая ключи с тем же декодированным значением после экранирования, запрещён.
2. Проверяем точные версии, поля и обязательные операции. Программа C01 проверяется с объявленными параметрами и ссылками на объёмы. Каталоги привязок и список вкладов проверяются до вычисления.
3. Сортируем вклады по их идентификаторам. Порядок узлов FGM-0 и остальных массивов сохраняется. Ключи объектов рекурсивно сортируются по кодам символов UTF-16.
4. Кодируем компактный JSON без пробелов, BOM и завершающего перевода строки. Конечные числа binary64 записываются по правилам ECMAScript для JSON, включая общий вид `0` для положительного и отрицательного нуля. Строки кодируются по правилам JSON для ECMAScript. Результат переводится в UTF-8. Правила записи чисел и сортировки ключей совпадают с JCS на допустимых значениях схемы. [RFC 8785](https://www.rfc-editor.org/rfc/rfc8785.html)

При передаче объекта напрямую исполнитель фиксирует снимок обычных данных JSON. Он принимает плотные массивы, обычные объекты с собственными перечисляемыми полями данных и допустимые примитивы. Геттеры, скрытые свойства, символы, прокси и циклы отклоняются с `E_PACKAGE`.

## Хеши и семена

Хеш — SHA-256 канонических байтов JSON-массива `[domain, value]`. Для вычисления используется та же запись ключей, строк и чисел. Результат записывается строчными шестнадцатеричными символами.

| Домен | Значение `value` | Назначение |
| --- | --- | --- |
| `fgm:model:1` | `{format, interpreter, model}` | Идентичность семантической модели, включая сохранённое семя и дескрипторы объёмов. |
| `fgm:package:1` | Полный нормализованный пакет | Идентичность сборки вместе с рецептом генерации. Изменение версии генератора, ресурса или обязательного параметра изменяет этот хеш. |
| `fgm:seed:1` | `{generation, purpose}` | Воспроизводимое семя для заданного назначения `purpose`, имеющего вид идентификатора. |

Семя модели может быть вычислено с назначением `model` и записано в пакет. Чтение сохраняет выбранное семя. Новые семена по рецепту вычисляются явно для каждого назначения. Изменение рецепта при том же результате меняет семена по рецепту и хеш пакета. Хеш модели меняется, когда меняются её сохранённые входы. Сопоставление по хешу использует сериализованную модель. Математически эквивалентные программы с разной структурой могут иметь разные хеши. Ключи визуального кэша дополнительно учитывают параметры, от которых зависит визуальный результат.

## Проверка

`E_JSON` означает ошибку входных байтов, синтаксиса либо повтор ключа. `E_PACKAGE_VERSION` означает неизвестную версию. `E_PACKAGE` обозначает неверный состав манифеста, `E_FIELD` — неизвестный вид поля или неверный состав его полей, а `E_SEED` — недопустимое назначение семени. Ошибки программ и композиции следуют C01/C03. Неизвестные обязательные узлы отклоняются во всех программах пакета. Совместимость будущих редакций вводится явным обновлением схемы.

Тесты сравнивают [канонический файл](../tests/fixtures/c04-panel.fgm.json) и [эталонные хеши](../tests/fixtures/c04-panel-expected.json), а также выполняют точечную выборку после повторной записи. Эталонные значения вычислены независимо от исполнителя. Синтетическая панель содержит сквозной проём и вклад металла с более высоким приоритетом.
